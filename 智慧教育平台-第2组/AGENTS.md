# 项目工作规范

本文件适用于 `D:\智慧教育课程\智慧教育平台` 及所有子目录。执行任务前读取相关 README、需求依据及更深层的 AGENTS.md；用户明确指令优先，遇到冲突应说明依据与影响。

## 当前开发边界

- 当前仅进行架构准备、目录建设和规范维护。未得到新的业务开发任务前，不开发业务功能，不接入完整若依，不安装依赖、不初始化数据库或 Git。
- 不伪造 `pom.xml`、`package.json`、锁文件、Spring Boot 启动类或“可运行”结论；不生成空 Controller、Service、Mapper、Entity、Vue 页面或假接口。
- 不擅自锁定 Java、Spring Boot、Vue 等依赖版本，不编造启动命令、测试结果或第三方接入能力。
- 已创建的空目录用于明确分工，不为保留目录添加 `.gitkeep`、空白 README 或同质化编号文档。

## 目录与命名

- 唯一正式工程根为本目录；不得再创建同名嵌套工程或在外层建立第二套业务代码。
- 后端统一 `backend/`，教学业务统一 `backend/ruoyi-education/`；九个领域命名固定为 `course`、`resource`、`prepare`、`classroom`、`activity`、`assignment`、`learning`、`analysis`、`ai`。
- 规划 Java 包根为 `com.ruoyi.education`，领域位于该包下。接入真实基础工程时先核对包名、扫描路径和模块依赖，不把领域目录拆成九个 Maven 模块。
- 前端角色页面放 `frontend/src/views/education/{teacher,student,admin}`；公共业务 API 放 `frontend/src/api/education`，共用业务组件放 `frontend/src/components/education`。
- SQL 放 `sql/`，开发文档放 `docs/`，有效原型及所需资源放 `prototypes/`。详细命名规则随选定的上游代码风格统一，新增 Java 包使用小写，文档采用有意义的英文短横线名称。
- 登录、身份、权限、请求客户端和基础布局复用最终若依能力，不为三端重复建设。系统基础能力与教学业务保持职责分离。

## 保护现有成果

- 外层 `智慧教育课程需求分析.docx` 与 `功能架构优化方案 V2.0.md` 是受保护来源，不删除、不覆盖。修改正式开发文档不得反向重写原始需求。
- 历史设计、用户代码和未知文件先读内容再判断。不得以“看似占位”作为删除依据，也不得覆盖未提交的用户变更。
- 旧文件删除必须先有完整清单、工作区外可恢复备份、数量与关键哈希验证、迁移核对，并等待用户对明确清单的最终确认。
- 本轮 `docs/migration-report.md` 中的候选仅为待审清单，不构成删除授权。不得直接递归删除旧目录，也不得删除外部备份。
- 以后若发现本轮未扫描到的旧原型或骨架，单独登记、补充备份并重新核对，不沿用本次校验结果直接删除。

## 业务与依赖边界

- 基础模块不得反向依赖教学业务；业务领域不得直接访问其他领域 Mapper 或私有表，跨域通过清晰的服务契约协作。
- 课程内容与教学班发布范围分离；所有教学接口、下载、导出、实时连接和 AI 检索均须在服务端检查身份和数据范围，不能仅靠菜单隐藏。
- 模板与活动实例分离；提交具备幂等和版本记录；课堂小作业复用统一作业引擎。
- 教师私有备注、未公布答案、学生明细不能自动进入投影或学生端。AI 初评与正式成绩分离，成绩必须教师确认发布。
- 统计保留来源、目标快照、分母、时间窗口和版本；缺失数据不能写作零值掌握度。
- 需求 P 分级与方案 M 分级分开记录，范围变更注明来源、状态和评审责任，不自行删减原需求。

## 工作方式与交付

1. 修改前定位目录、读取来源，检查是否已有实现；有 Git 后先检查工作区状态。
2. 仅改当前任务必要文件；变更契约、权限、状态或数据含义时同步更新相关文档。
3. 架构文档修改检查路径、引用、规划与实现状态和来源一致性。获得开发授权后，按实际改动运行相关检查，不为低影响文档维护构造镜像测试。
4. 不把密码、学生个人数据、访问令牌或真实服务凭据写入代码、示例、日志或原型。
5. 交付说明实际修改、验证证据、未完成项与待决策项；无运行环境时明确说明，不宣称测试通过。
