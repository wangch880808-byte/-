## 1. 第 1 组（身份、权限、公共能力）

### R-1.1 可信身份字段契约 —— P0

**要什么**：一份写死的字段表，说明业务接口能从登录态拿到什么。

| 字段 | 现在我们从哪取 | 需要确认 |
|---|---|---|
| `userId` | `SecurityUtils.getLoginUser().getUserId()` | 类型 `Long`；**是否要改成字符串输出**（见 Q5） |
| `nickName` / `userName` | 同上 `getUser()` | 是否稳定、是否可空 |
| `deptId` | 同上 | 组织归属是否就用它；顶层部门怎么取 |
| `roles[].roleKey` | 同上 | 键名是否就是 `admin`/`teacher`/`student` |
| `isAdmin()` | `SysUser.isAdmin()` | 是否等于 `user_id=1`，与 `role_key=admin` 是否等价 |
| `/getInfo` 的 `permissions` | 前端 `v-hasPermi` | 超管是否为 `*:*:*` |

**验收样例**：用 admin/teacher/student 三个账号调 `/getInfo`，字段齐全；停用账号拿不到有效令牌。

**没有它时的临时方案**：我们已按上表实现，但一旦 1 组改字段名或类型，所有 403 判定会静默失效——所以必须书面确认。

### R-1.2 角色键与教务管理员 —— P0

**要什么**：
1. 确认 `sys_role.role_key` = `admin` / `teacher` / `student` 三个键稳定存在。
2. 新建受限角色 `edu_admin`（教务管理员），并明确它：
   - 能看到哪些菜单（我们这一批：学期管理、班级管理、教师管理、学生管理、组织架构管理）；
   - 数据范围是「本组织」还是「全部」（影响 §3 的所有"管理员"分支）；
   - **不能**获得超管权限（不能改角色、不能看监控）。

**为什么卡我们**：2-03 的验收条件是"管理员能查看并调整教学班成员"，而"管理员"在代码里当前等于超管。没有 `edu_admin`，这条只能按超管验收，不满足 1-02 的边界要求。

**验收样例**：`edu_admin` 登录 → 五个页面可读可写；`/system/role` 返回 403。

### R-1.3 权限标识注册 —— P0

**要什么**：在「系统管理 → 菜单管理」建下列权限标识并绑到角色（我们只在后端加 `@PreAuthorize`，菜单由 1 组建）。

| 权限标识 | 用途 |
|---|---|
| `education:term:list` / `:add` / `:edit` / `:current` | 学期 |
| `education:class:list` / `:add` / `:edit` / `:member` / `:teacher` | 教学班、成员、授权 |
| `education:course:list` / `:add` / `:edit` / `:publish` / `:bind` | 课程 |
| `education:directory:list` | 教师/学生名册、组织树 |
| `education:scope:read` | 跨组作用域查询 |

**注意**：现在**不能**直接加 `@PreAuthorize`。数据库里还没有这些 perms，加了会让教师、学生全部 403（超管因 `*:*:*` 不受影响），演示立刻坏掉。正确顺序：1 组先建菜单 → 角色授权 → 2A 再加注解 → 回归。

**验收样例**：教师账号的 `/getInfo.permissions` 里没有 `education:class:add`；管理员有。

### R-1.4 用户/部门只读查询 —— P0（需裁决）

**现状**：我们的 `EduPortalMapper.xml` 直接 join 了 `sys_user`、`sys_user_role`、`sys_role`、`sys_dept`（教师名册、学生名册、组织树、成员姓名）。

**这违反「不直接读别组私有表」的约定**，需要 1 组二选一：

- **方案 A（推荐）**：1 组提供只读查询接口，例如
  `GET /system/user/list?roleKey=teacher&deptId=`、`GET /system/dept/tree`、`GET /system/user/{id}`；
  我们改调接口，删掉 join。
- **方案 B**：1 组书面确认「教学模块可只读 join 系统表」，并把这条写进 `api-contracts.md` 的跨领域契约表。此时我们要补一条约束：**只读、不写、不缓存**。

**验收样例**：教师名册页数据与「系统管理 → 用户管理」一致；停用账号不出现在名册里。

### R-1.5 账号停用与令牌失效 —— P0

**问题**：教学班撤权我们不缓存，下一次请求就生效。但**账号停用**（`sys_user.status='1'`）是否立刻踢掉已发令牌，取决于若依的 Redis 令牌策略。

**要什么**：明确以下三种情况的生效时点，并给一个可验证的样例：
1. 停用账号后，旧令牌还能不能用？
2. 改角色（teacher → student）后，旧令牌里的权限是否刷新？
3. 删除账号后，`userId` 是否会被复用（影响历史数据归属）？

**影响**：2-01 完成判据写的是"撤权、调班后访问边界立即生效"。班级内的撤权我们已保证；账号级的要靠 1 组。

### R-1.6 403 语义统一 —— P1

**现状**：若依公共 `src/utils/request.js` 对 `code !== 200` 一律 `ElNotification.error` + `reject('error')`，页面拿不到 403 与 500 的区别。2B 在 `src/api/education/http.js` 里自带了一套（含 401 重登、403 无权限）。

**要什么**：1-03 在公共请求层补 `code === 403` 分支，`reject(new Error(msg))` 并带 `error.code = 403`。补齐后我们删掉自带实现，三端请求语义一致。

### R-1.7 审计 —— P1

**要什么**：确认业务侧写审计的方式。我们计划在以下操作加 `@Log(title="教学班管理", businessType=...)`：
成员加入/移出、教师授权/撤权、课程发布/撤回、绑定/解绑。
查询直接用若依 `/monitor/operlog`。

**验收样例**：撤权后能在操作日志按操作者、时间查到，且带 `classId`。

### R-1.8 教务管理员数据范围 —— P1

**要什么**：`edu_admin` 只能看本组织时，我们需要一个可信的「当前用户可见组织」来源（`deptId` 顶层、或 1 组给 `getDataScope()`）。
**否则**：我们的列表接口会返回全校数据，越权。

### R-1.9 演示账号与数据 —— P0

**要什么**（G0 关口前）：

| 账号 | 角色 | 要求 |
|---|---|---|
| `eduadmin` | `edu_admin` | 属于学校组织，不是超管 |
| `teacher01` / `teacher02` | teacher | 分属同一学校、不同院系；`teacher02` 不任教 1 班，用于越权用例 |
| `stu01`～`stu10` | student | `stu01`～`stu05` 在软工 1 班，`stu06` 在软工 2 班，`stu07` 不在任何班（空数据用例） |

**验收样例**：`stu07` 登录 → 课程列表为空且不报错。

## 2. 第 3 组（资源、题库、课前）

### R-3.1 章节与知识点写接口 —— P0（当前最大缺口）

**现状**：我们能**读** `edu_course_unit` / `edu_knowledge_point` 并在课程详情展示；但**写**的接口没有。`pages-teacher.js` 里也写着"章节编辑由第 3 组（3-03）实现"。

**要什么**：二选一，必须书面定：
- **A**：3 组提供 `POST/PUT/DELETE /education/resource/units`、`/knowledge-points`（我们只在详情页调用，不实现写）。
- **B**：3 组确认"章节属于课程建设，由 2 组代管"，我们补这组 CRUD（约 1 人日），3 组只做资源挂载。

**为什么卡**：2-04 的完成判据是"教师建课后能进入课程详情"。只读目录可以算通过，但 `3-03 课程建设` 页面需要写章节，没有这个接口 3 组也做不了。

**验收样例**：新建章节 → 刷新详情树结构正确 → 4 组能按 `unitId` 定位页码。

### R-3.2 资源计数（P1）
课程卡片当前只显示 班级数/学生数。若要做"资料 N 个"，需要 3 组提供按 `courseSpaceId` 的计数或摘要接口。**M0 可不做**。

### R-3.3 预习任务字段口径（P0）
3 组发布预习时，落库必须用我们的 `classId` / `courseSpaceId` / `memberId`，不要自建"班级名称"字段。要求 3 组在契约里引用 §6 字段字典。

## 3. 第 4 组（课堂与同步）

### R-4.1 进行中课堂查询 —— P1
**要什么**：`GET /education/classroom/active?classId=` → `{ sessionId, startedAt, status }`，无则 `null`。
**用途**：教师「我的课程」卡片显示「正在上课」、学生「在修课程」显示「进入课堂」。4-03/4-04 已负责页面，这条只是让课程入口有状态。**M0 可用静态入口替代**。

### R-4.2 事件与快照必须带班级范围 —— P0
课堂事件、公开页快照都必须带 `classId`（和 `courseSpaceId`），并在订阅、重连、补查三处校验。我们提供 `EduCourseAccessService.membership()`，请在连接建立与每次重连时调用。**不接受"WebSocket 已连接"当作权限通过。**

## 4. 第 5 组（作业、评价、学情）

### R-5.1 课程维度任务摘要 —— P1
**要什么**：`GET /education/assignment/summary?courseId=` → `{ pending, submitted, graded, published }` 计数。
**用途**：课程详情「作业」页签角标、教师待办入口。**M0 可先显示空状态**。

### R-5.2 提交与成绩引用口径 —— P1
作业目标、提交、成绩都要带 `classId` + `memberId`，统计口径注明"分母 = 发布时的目标人数快照"。我们提供 `activeMembers()` 生成目标名单。

## 5. 第 6 组（总览、消息）

### R-6.1 课程/班级公告读取 —— P1
6-02 负责公告写入与接收范围。若课程详情要展示本课公告，需要 6 组给 `GET /education/notice/course/{courseId}`。**M0 可先空**。

### R-6.2 总览取数 —— P1
6-01 的课程数、教学班数、学生数**直接调** `S2`/`S6`，不要自己 join 我们的表重算。我们保证这几个接口的数字与课程/班级页面一致。
