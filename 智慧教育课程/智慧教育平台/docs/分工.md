# 智慧教育课程平台开发分工

> 版本：1.1 任务草案｜日期：2026-10-23｜团队：6 个小组，每组 2 人，共 12 人

## 1. 先看这三条

1. 本文给 12 位队员分配非 AI 任务。教师 AI 教学助手、学生 AI 学习助手、管理员 AI 对话与模型控制台，以及 AI 生成、检索、初评等能力，均由项目负责人本人后续开发。六组不得把这些内容写进自己的交付承诺，也不用制作假聊天页。需要与 AI 对接时，由项目负责人另开接口交接任务。
2. 当前项目只有管理员（`admin`）、教师（`teacher`）、学生（`student`）三种业务登录身份，不新增“教务管理员”角色。若依三角色登录、验证码、获取用户信息、获取路由及退出已有本机联调结果。登录页已跳转至三个运行页面；这些页面已有登录态与角色校验、静态导航、面包屑、页签和退出按钮，直接复用。业务内容仍是占位，静态菜单尚未关联业务接口与服务端对象权限。现有账号和教学演示数据见[联调账号](demo-login-accounts.txt)，接口事实见[接口协作约定](api-contracts.md)。
3. 首批交付以[功能架构 V3.0](../../功能架构优化方案.md)的教学闭环为目标：教师建课并绑定教学班 → 发布资料与预习 → 开课与学生跟页、签到和答题 → 布置并提交作业 → 教师确认发布成绩 → 师生查看获授权的反馈。每项功能必须用真实接口和服务端对象权限完成，不能只让原型页面显示静态文字。

三个导航原型仍用于核对入口名称：[教师端](../prototypes/console-navigation-v1/teacher.html) 12 项、[学生端](../prototypes/console-navigation-v1/student.html) 13 项、[管理员端](../prototypes/console-navigation-v1/admin.html) 38 项，共 63 项。63 是菜单入口数量，不是本阶段必须完成的独立业务数量。M0 为首批闭环；M1 在 M0 稳定后按工时认领；证书、独立实训、单项能力评测、第三方登录等待确认或 M2 内容暂不派开发任务。未实现的入口在正式角色菜单中不开放，原型保留作设计参考。

**AI 范围说明：**V3.0 将双 AI 助手列入产品方向，原方案中的基础问答优先级为 M0。本次只调整人员归属和交付排期，不宣称该需求已完成或已取消；项目负责人单独安排开发与验收，六组的非 AI 验收不以 AI 完成为前提。

## 2. 人员与交付方式

每组 A 负责本组数据、后端、服务端权限和接口契约；B 负责本组页面、交互和联调。A、B 均须提供正常、空数据、无权限、失败四类验证。每个任务编号对应一个父 Issue，复杂任务再拆子 Issue；父 Issue 只能有一名直接负责人。前后端约定对象 ID、字段、状态、错误和时间后再编码，不从别组私有表直接读取数据。

| 小组 | A 的主责 | B 的主责 | 首批交接对象 |
| --- | --- | --- | --- |
| 第 1 组：1A、1B | 账号、角色、权限、审计与公共接口 | 在现有三端页面接入业务入口、课程/教学班上下文及系统管理页面 | 向所有组提供可信用户 ID、角色及统一的拒绝无权限方式 |
| 第 2 组：2A、2B | 学期、教学班、成员、课程与授课授权 | 教务管理及师生课程页面 | 向第 3～6 组提供课程、班级和有效成员资格 |
| 第 3 组：3A、3B | 资源、题库、备课和预习发布 | 教师资料/课前页面及学生资料/预习页面 | 向第 4、5 组提供已授权、已发布的资源版本和预习任务 |
| 第 4 组：4A、4B | 课堂会话、公开页同步、签到与随堂题 | 教师控制台、投影公开页、学生跟课页 | 向第 5、6 组提供课堂状态与活动结果 |
| 第 5 组：5A、5B | 统一作业、提交、批改、成绩发布和学习证据 | 师生作业、反馈与学情页面 | 向第 6 组提供有来源和口径的任务及评价数据 |
| 第 6 组：6A、6B | 三端总览聚合、公告、留言与通知 | 三端工作台、消息和管理员看板 | 消费第 2～5 组授权接口，不复制其课程、课堂或作业数据 |

第 1 组在已有三端导航和登录态代码上维护公共请求、业务入口与权限处理；其他组各自实现业务页面。第 2 组维护教学班成员资格，第 1 组维护若依账号与角色，不能把账号角色直接当作某个教学班的访问许可。第 5 组维护统一提交与评价；第 3 组的预习测验和第 4 组的课堂小作业复用它，不各建一套提交记录。

## 7. 队员怎样把任务提交到 GitHub

队员提交任务到 GitHub，简洁流程如下：

**推荐方式（分支 + PR）**

1. `git clone` 仓库并进入目录。
2. 拉取最新 `main`，新建自己的分支：`git checkout -b feature/任务名`。
3. 修改文件后提交：`git add .` → `git commit -m "说明做了什么"`。
4. 推送分支：`git push -u origin feature/任务名`。
5. 在 GitHub 页面点 **Compare & pull request**，发起 PR。
6. 等队友审查通过后，点 **Merge pull request** 合并。不要直接改 `main`。
