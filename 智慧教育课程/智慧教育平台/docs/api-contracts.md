# 接口协作约定

本文件提炼原始需求第 10.3 节与 V2.0 方案第 5、8 节的接口约束，并补充团队协作规则。若依基础登录接口已接入；以下教学业务接口仍为待评审方案，未实现的路径与权限标识不是已冻结协议。

## 已实现的三角色登录契约

- `GET /captchaImage` 获取验证码；启用时，`POST /login` 需提交 `username`、`password`、`code`、`uuid` 和所选 `role`。`role` 只能为 `admin`、`teacher`、`student`；服务端在认证成功后、发令牌前核对账号角色。不传 `role` 保持若依原有登录兼容性，平台登录页始终传值。
- 成功响应沿用若依 `AjaxResult`，`code=200` 且含 `token`；角色不匹配或入口无效时不返回令牌。登录页携带令牌调用 `GET /getInfo` 与 `GET /getRouters`，角色页加载时再次核验，退出调用 `POST /logout`。
- 当前 `admin` 使用本机若依超级管理员演示账号；教师和学生为项目角色，`sys_user.user_id` 与教学班师生关联表的 `user_id` 对应。登录角色只确认身份，教学班、课程、资源和操作权限仍须在各业务接口服务端逐项校验。静态原型菜单不是授权菜单。

## 契约先行

每个接口任务至少记录：需求/变更来源、所属领域、调用角色、业务对象、请求和响应字段及类型、必填与空值、状态前置条件、对象数据范围、幂等与并发规则、错误情况、验收示例、负责人、消费者及兼容策略。

HTTP 业务入口建议集中在 `/education` 命名空间，权限标识可按 `education:<domain>:<operation>` 组织，均为待接入评审的命名建议，不是已有 URL、权限配置或已冻结协议。请求方式应符合真实操作语义，不用 GET 改写状态。

复用所选若依的成功/分页/错误包装以及统一请求客户端；业务层补充对象 ID、版本、状态、服务端时间和可定位错误。禁止前后端各自发明不同的返回结构。

## 跨领域契约归属

| 提供方 | 应提供的契约 | 主要消费者 |
|---|---|---|
| course | 课程/教学班归属、成员资格、教师授权与知识点标识 | 全部教学领域与各端页面 |
| resource | 授权资源版本、转换状态、题目与评分标准快照 | prepare/classroom/activity/assignment/ai |
| prepare | 备课方案、预习任务和活动模板快照 | 教师/学生端、课堂入口编排 |
| classroom | 会话状态、公开页状态、重连快照 | 教师控制台、投影、学生课堂、活动入口（详见 [课堂接口草案](api-contracts-classroom.md)） |
| activity | 激活、关闭、签到、随堂答题及实例结果 | 三端授权页面、learning、analysis |
| assignment | 统一作业发布、提交版本、复核与正式评价 | activity、教师/学生端、learning、analysis |
| learning | 本人轨迹、错题、补学及来源引用 | 学生端、授权教师端、analysis |
| analysis | 有口径、样本及截止时点的授权统计 | 教师/学生/管理员各自授权页面 |
| ai | 异步建议任务、状态、结果及用量审计 | 备课、答疑与作业服务；不直接写正式成绩 |

## 身份、字段与时间

- 操作者与学生身份由服务端可信认证上下文取得，不能通过传入 `studentId` 或角色参数冒充。课程、教学班、资源与任务间的关联须一并核对。
- 明确 ID 是否采用字符串传输、时间格式与时区、小数精度、分页边界及空值含义；接入时评审，不在本轮伪造最终字段定义。
- 服务器负责开放、截止、迟到与发布时点。响应提供服务端时间语义；客户端倒计时只用于展示。
- 对象更新需约定版本冲突处理。关闭活动、结束课堂与提交交错时，有效性依据服务端明确的原子状态与接收规则判定，不能使用客户端时间绕过截止。

## 幂等、快照与修订

创建活动、提交答案/作业、结束课堂、发布成绩及回调处理应定义幂等边界。契约须说明键的作用域与有效期、同键同载荷重试返回何种结果、同键异载荷如何冲突、失败后如何重试。

幂等键不能替代业务唯一约束：即使客户端换键，也不能重复生成有效签到或随堂作答。允许改交的作业通过显式版本转换处理，保留原提交；教师补签、补答、改分记录操作者与原因。

发布目标、资源、题目、答案与量规快照随任务固化。公布解析、确认成绩和成绩发布是不同操作，需分别校验权限与状态。

## 实时课堂

传输方式尚未选定，可能的 WebSocket、SSE 或补查机制需先做实际网络验证。无论采用何种方式，都应满足：

1. 订阅和重连均校验身份及教学班范围；退出班级或撤权后的连接需撤销访问。
2. 事件按对象带活动/会话标识、版本和序号，前端丢弃过期更新。作用域、连续性与缺口处理在契约中定义。
3. 重连先获取服务端最新快照，再补订阅或补查；快照与事件的版本衔接要避免漏更新。恢复本人已成功提交的结果。
4. 教师私有事件与公开投影/学生事件分别裁剪载荷，公共通道不得广播隐藏答案和成绩明细。
5. 推送失败或丢消息不能改变已落库的有效提交；客户端可查询确认结果，服务端仍是权威状态源。

## AI、文件与外部依赖

- AI 采用可追踪任务语义：创建返回任务标识，查询或鉴权回调获取结果；重复回调去重、结果结构校验、超时/失败可回退人工。调用方复核结果关联版本后保存建议，不自动发布成绩。
- AI 检索只使用当前用户有权看到的课程资料，隐藏答案和其他学生信息不得作为学生问答上下文；结果应能追溯资料出处。
- 上传完成后执行文件检查、转换或索引，暴露处理中/成功/失败及受控重试语义；不能把上传成功当作课件可展示。
- 下载与导出在创建和实际获取时检查范围，不使用永久公开地址暴露教学资料；撤权与资源下架后旧链接也应失效。
- 外部平台逐项确认字段权威来源、同步方向、外部 ID、授权、分页、限流、重试、回调校验及负责人。外部成绩不能直接覆盖平台已确认成绩，冲突转人工。

## 契约验收与变更

评审至少包含本班/外班、未公布答案、重复提交、并发结束、过期请求、断线重连、成员退出、AI 超时与重复回调等正常及失败示例。接口提供方和消费方共同确认字段及错误处理；数据库负责人确认唯一性和版本策略。

契约变更先记录受影响调用方和兼容期，同步更新实现、文档与必要验证。当前只有基础登录接口完成本机联调；教学业务接口尚无运行验证结论。
