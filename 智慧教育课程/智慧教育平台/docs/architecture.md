## 核心对象与拥有者

| 对象 | 主要拥有者 | 必须保留的区分 |
|---|---|---|
| 课程空间、正式课程、教学班、章节与知识点 | course | 内容资产不等于教务目录；教学班是发布与学生数据范围 |
| 资源、题目、评分标准及版本 | resource | 资源本体与按班发布关系分离；引用需定位版本 |
| 备课方案、预习任务和活动预设 | prepare | 草稿/模板不会自动产生对学生生效的活动 |
| 课堂会话和公开演示状态 | classroom | 课堂公开页与教师私有控制信息分离 |
| 签到、实时题及活动目标快照 | activity | 实际活动有独立 ID 与状态，可不关联课堂会话 |
| 作业、有效提交、批改建议与正式评价 | assignment | 课堂小作业与课后作业复用同一提交/批改能力 |
| 学习轨迹、错题与补学记录 | learning | 来源可追溯；重做和补学不能覆盖原提交或正式分数 |
| 班级、学生和知识点统计 | analysis | 统计读模型不是正式成绩的拥有者 |
| AI 任务、模型/模板版本和调用记录 | ai | 建议和生成内容须经业务方确认；模型不可自行发布成绩 |

账号、角色、部门和菜单复用若依 system；教学班成员及任课关系属于 course。避免将“若依部门数据权限”直接等同为“教学班授权”，二者需明确映射。

## 教学流程与状态

课程内容建设 → 绑定授权教学班 → 备课/预习 → 课堂会话与公开课件同步 → 实例化签到/实时题/小作业 → 作业提交和教师评价 → 发布反馈 → 错题补学与统计 → 创建下一轮教学草稿。

状态名称、字段枚举与精确转移表尚需接口评审，不将下述业务规则视为已实现枚举：

- 模板可保存、复制、预览，只有明确激活或发布才生成有效任务/活动；学生不能从草稿链接提前参加。
- 课堂允许无备课方案快速开始；结束与归档要记录资源版本、公开页进度及关联活动结果。进行中的活动如何关闭由服务端编排，结束请求具备幂等。
- 保留教学班内独立签到/独立发题能力，`sessionId` 关联不能强制覆盖所有活动场景。
- 同一教学班同一时刻最多一个进行中的签到、一道进行中的实时题；并发控制需在服务端原子完成。
- 提交、改交、迟交、重开和补签必须校验服务端时点、规则版本与身份；补救留理由和修订历史。
- 建议批改 → 教师复核确认 → 正式发布。未发布成绩不可通过页面、接口、导出或 AI 上下文泄露；撤回与更正有原因和发布版本。

## 数据完整性约束

1. 课程归属、教学班、学期、成员生效/退出时间和任课角色应可追溯。活动目标人数来自发布快照及有记录的合法调整，不随当前名单悄然重算历史。
2. 发布或发题时固定使用的题目、答案、评分量规、资源版本与截止规则。题库后续编辑不得改写既有作答含义。
3. 有效提交按活动与学生唯一确定；允许多版本改交时只保留一个当前有效版本，历史版本不得删除覆盖。幂等键作用域、唯一约束与并发策略联合评审。
4. 成绩绑定具体提交、评分规则、教师确认与发布版本，AI 初评另存。更正触发受控重算，错题重做形成新证据。
5. 学习事件保留去重标识、来源资源版本、服务端时间与有效区间。多端重叠和重复观看不能无限累加覆盖率。
6. AI 任务记录模型、提示模板、知识库/资源版本、耗用和状态，按权限与期限存储输入和结果。敏感原文不得默认永久保存。
7. 已选择 MySQL 作为数据库设计方言；[V3.0 M0 数据库设计](database-design.md)列出 44 张教育业务表。建表与关键约束已在 MySQL 8.0.43 实测；MySQL 8.0.46 未验证，待 8.0.46 环境复核；项目库部署、若依 ID 对齐、迁移方案和历史数据保留方式仍待评审。

## 权限与公开内容

访问控制同时检查用户身份、操作权限和课程/教学班对象范围；覆盖详情、下载、导出、实时订阅、历史记录与 AI 检索。管理员细分教务和超级管理员，默认不能改教师已确认成绩。

公开投影/学生跟课仅接收明确公开的课件、题目、倒计时和获准匿名统计。教师备注、标准答案、学生姓名成绩及私有 AI 建议不进入公开载荷。服务端生成公开数据视图，不把含私密信息的完整对象广播后交给前端隐藏。

预习门槛默认提醒；若以后启用前置限制，需显式配置、提示及有理由的豁免。试讲与正式教学分开，体验班邀请、真实学生参与、数据留存需学校规则确认。

## 统计口径

下列为原需求第 10.2 节建议口径的保留，**尚需业务评审**。全部看板、明细与导出应携带教学班、时间窗口、截止时点、口径版本、分母和样本数；分母为零或缺失证据时显示暂无数据。

| 指标 | 建议计算规则 |
|---|---|
| 预习完成率 | 完成全部必选项人数 ÷ 有效目标人数；批准豁免剔除，人工完成单列 |
| 有效视频覆盖率 | 指定片段内去重有效观看区间长度 ÷ 指定片段长度；不同于学习时长 |
| 答题参与率 | 成功提交人数 ÷ 有效目标人数；合法补答标识并更新版本 |
| 答题正确率 | 满分提交人数 ÷ 有效提交人数；另给出全员正确人数与应答人数 |
| 作业完成率 | 有效提交的学生作业对数 ÷ 到期应交学生作业对数；迟交和未到期单列 |
| 作业平均分 | 已发布正式分之和 ÷ 已发布成绩记录数；跨不同满分先换算百分制，未交/未发布不当作零分 |
| 出勤率 | 正常及迟到人数 ÷ 有效应到人数；迟到单列，批准免签剔除 |
| 知识点评价表现 | 关联正式评分项得分之和 ÷ 对应满分之和；不是已证明掌握程度 |

不默认合成课程总分或 AI 掌握度。预警阈值、窗口、样本下限和权重需单独批准。

## 保留的范围差异

| 差异 | 来源含义 | 后续处理 |
|---|---|---|
| 同步课堂与 PPT | 新方案提升到 M0，原需求部分授课联动后置 | 评审首版承诺与技术验证范围 |
| 教师自建课程与试讲 | 新方案增加自助创作和受限体验场景 | 确认与正式教学班绑定及学生加入规则 |
| AI 初评、个人学情与文本答疑 | 原需求建议 P0，新方案部分列 M1 | 不直接删减原承诺；由项目负责人确认排期 |
| 直播、实时 AI、深度 PPT 动画、第三方同步 | 新方案后置或需专项 | 不提前生成菜单或承诺兼容性 |

这些分歧在 [开发路线](development-plan.md) 中列为评审门槛，当前不存在“已确认全部范围”的结论。
