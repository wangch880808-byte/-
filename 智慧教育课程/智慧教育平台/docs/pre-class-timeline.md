## 1. 这次改了什么、什么没改

需求是把「课前准备」抽象为一条大时间轴：教师按时间轴自行设置环节里的内容（上传资料让学生看、发布习题让学生做），学生端只看到这些环节里的任务。

**保持不变（原有框架）**

- `frontend/login.html`、`teacher.html`、`student.html`、`admin.html`、`login.js`、`role-home.js` 未改；三端登录态、角色校验、导航、面包屑、页签、退出逻辑照旧。
- `MENU` 的 `g / i` 编号、`?g=&i=` 路由、`window.Group3App.render(gi, ii)` 挂载契约未改。
- 前四轮未改后端；第五轮（删除环节）**只新增** `POST /education/group3/stages/remove` 与 4 条 Mapper 归档语句、4 处查询过滤，未改任何既有接口的路径、字段或返回结构，未改表结构、未物理删除数据。详见 [接口协作约定](api-contracts.md) 末节。
- 页面仍由 `backend/ruoyi-admin/pom.xml` 把 `frontend/` 资源拷到 `static/`；`target/classes/static/` 是构建产物，未手工修改。

**改动**

- 重写 `frontend/group3.js`：教师「课前准备」改为时间轴工作台；教师「课程建设」保留三个资产页签并补强失败提示与归档入口；学生「课程资料」「课前学习」改为同一条时间轴的两个视角。
- 增补（第二轮，2026-11-08）：一次课前学习的环节按开放时间编号 `1..N`，教师端新增环节步骤条总览；每个环节新增**独立的作答 / 编辑页**（占满主内容区），顶部步骤条与底部按钮可跳上一 / 下一环节；作答草稿按环节隔离；用 `#stage=<key>` 支持刷新与前进后退。
- 增补（第三轮，2026-11-08）：三个「添加环节」表单从拥挤弹窗搬进**独立分步创建页**（`#create=<flow>`，仍只在 `#group3Content` 内渲染）；新增可搜索的**资产选择器**，课程资源库 / 题库里已有的内容直接引用版本 ID 发布，不再重复上传或重复录入题目；教师、学生总览的统计与环节条收进可折叠概览区、工具栏拆成两行；「课程建设」增加「选用已有资料建环节」「用题库题目建预习」入口。详见第 6 节。
- 增补（第四轮，2026-11-08）：「提交本环节预习」不再静默消失，详见第 7 节边界第 12 条。
- 增补（第五轮，2026-11-08）：**删除环节**（教师端卡片 / 详情 / 独立环节页，二次确认后调用真实归档接口）；**编号口径改为按堂课**——「课程 / 教学班 / 上课日期」确定一堂课，每堂课内部从 1 重新编号，换班级、换课程、换日期不延续上一堂课的序号；总览步骤条按堂课分区、顶部可直接切换课堂，上下环节只在同一堂课内跳转；创建页写明目标课堂。详见第 9 节。
- `frontend/group3.css` 末尾追加时间轴、独立环节页、分步创建页、资产选择器与按堂课分组样式（浅色主题、响应式），原有类未删除、未覆盖破坏。

## 2. 时间轴模型：环节就是真实后端记录

没有引入「环节」这张新表，也没有本地草稿或演示数据。时间轴上的每个节点都由既有接口返回的真实对象归集而成，教师「添加环节」实际是调用既有写入接口。

| 环节类型 | 教师 / 学生 | 数据来源 | 定位时间 | 写入接口 |
| --- | --- | --- | --- | --- |
| 资料阅读 `MATERIAL` | 双方 | `GET /overview` → `resources[]`（教师，带 `releaseId/opensAt/closesAt`）；`GET /student/materials`（学生） | `opensAt` | `POST /resources` → `POST /releases` |
| 待编排资料 `DRAFT` | 仅教师 | `resources[]` 中未发布或 `processingStatus=FAILED` 的记录 | 无（置顶「待编排」组） | `POST /releases`（READY 才可发布）、`POST /resources/{id}/versions` |
| 预习习题 `QUIZ` | 双方 | `GET /preview-tasks` / `GET /student/previews` | `opensAt` | `POST /preview-tasks` |
| 备课包 `PLAN` | 仅教师 | `GET /plans` | 关联课次 `scheduledAt`，无则 `createdAt` | `POST /plans` |

一列数据对应一个环节：同一预习任务含多道题时，后端按 `assignment_item` 返回多行，前端按 `assignmentId` 聚合成单个环节并记录题量。状态由 `overview.serverTime`（教师端）判断未开放 / 进行中 / 已截止，学生端沿用后端返回的 `state`；客户端计算只用于展示，开放、截止、解析公布与提交有效性仍由服务端裁定。

教师端「备课包」是时间轴上标注「仅自己可见」的私有节点。学生接口根本不返回 `plans`，私有备注与未公布答案不会进入学生时间轴。

## 4. 页面交互一览

**教师「课前准备」**（`?g=1&i=2`）

顶部统计卡与环节步骤条收在一个**可折叠的「本堂课总览」区**（默认展开，可收起以留出阅读空间）；工具栏拆成两行：第一行是时间轴 / 列表视图切换与筛选，第二行是说明文字与「课程建设 / 生成备课包 / + 添加环节」。按日期分组的竖向时间轴（今天 / 明天 / 日期 + 现在标记），无开放时间的草稿置顶，每张卡片与列表行都标有「第 N / M 环节」。右侧为环节详情：内容、发布范围、开放窗口、处理状态、题目数与提交进度、教师私有备注，以及预览、版本、重新发布、上传新版本、撤回和「打开第 N 环节编辑页」等操作。「+ 添加环节」先选类型，再进入独立分步创建页（第 6 节）。

**教师「课程建设」**（`?g=1&i=1`）

课程资源（含处理状态与失败修复）、题库（版本与知识点）、章节与知识点（归档上传入口）三个页签；资源页签提供「选用已有资料建环节」、题库页签提供「用题库题目建预习」，都直接跳到对应的分步创建页并带上已有资产；另有「前往课前时间轴」跳转。

**学生「课程资料」「课前学习」**（`?g=1&i=1` / `?g=1&i=2`）

同一条时间轴，前者默认只看资料环节，后者默认看全部环节并可切「仅看待完成」；完成度条按服务端提交记录计算，无任务时不显示推测的掌握度。统计卡、进度条与环节步骤条收在可折叠的「我的课前学习进度」区，工具栏同样拆成两行，卡片与详情面板标有序号。点击资料环节可预览 / 下载，点击习题环节可作答、提交、查看已公布的反馈，并可一键切到另一个视角；卡片上的主按钮、详情面板按钮或步骤条序号都会进入该环节的独立页面。

## 5. 环节序号与独立作答 / 编辑页（第二轮增改）

**为什么这样设计**：用户要求「完成课前学习是一个过程」——教师发布 N 个环节，学生按环节逐一完成；每个环节相互独立，进入后是一张单独的编辑 / 作答页，可跳上一 / 下一环节；环节要标序号；作答区要占主要。原来的「时间轴 + 右侧窄详情面板」满足总览，但作答区太窄，因此**总览保留不动，新增一层独立环节页**。

**编号规则（第五轮修订：按堂课重新编号）**（`numberStages()` / `buildStageGroups()`，纯函数，已导出到 `__core`）

- **一堂课 = 课程 + 教学班 + 上课日期**：分组键 `YYYY-MM-DD|bindingId`，日期取 `opensAt` 的本地日历日。换一天、换教学班、换课程就是另一堂课，序号从 1 重新开始，不再把教师几节课的环节串成一条 `1..N`。
- 参与编号：每堂课内部已发布、学生可见的 `MATERIAL` 与 `QUIZ`，按 `opensAt` 升序；同一时间资料排在习题前，再按 key 稳定排序。`第 N / M` 的 `M` 只统计本堂课。
- 不参与编号：教师私有备课包 `PLAN`、待编排 / 处理失败草稿 `DRAFT`、已归档 `ARCHIVED`；显示「不计入序号」。
- 口径限制：学生资料与任务接口仍不返回 `lessonId`，教师资料发布也不带，所以「哪一天」用开放时间的本地日期近似，而不是数据库里的课次 ID。若后端补 `lessonId`，只需替换 `stageGroupKey()` 的分组依据，编号与导航逻辑无需重写。
- 总览步骤条按堂课分区，组标题显示「日期 · 课程 · 教学班」和本堂课 `1–N`；顶部「按课堂切换」chips 可快速换课程 / 教学班（走真实接口重新取数）；独立环节页只显示本堂课的步骤条，上下环节也只在本堂课内跳转，边界提示「已是本堂课第一个 / 最后一个环节」。
- 创建页写明归属：环节按「课程 / 教学班 / 开放日期」归入对应的一堂课，「发布设置」里可切换目标教学班，开放日期决定它属于哪一天。

**独立环节页**（`paintStage()`，替换整个 `#group3Content`，不动 `?g=&i=` 路由）

| 组成 | 说明 |
| --- | --- |
| 顶栏 | 返回总览、面包屑、`第 N / M` 计数器 |
| 环节头 | 类型、序号、状态、标题、说明、开放 / 截止、题量 / 版本页数 |
| 环节步骤条 | 独立页只显示**本堂课**的 `1..N`；总览按堂课分区显示全部组，标注类型、已提交 / 未开放，点任意序号直达 |
| 主体（占满宽度） | 学生习题：宽版题卡（题号、两列选项、简答文本域）、提交按钮、已公布反馈与关联资料；学生资料：内嵌分页预览 / 视频 / 外链 / 下载回退；教师：环节配置与状态、可执行操作（含删除环节）、题目清单、备课材料、内嵌资料内容 |
| 底栏 | 「上一环节 N：标题」「环节总览」「下一环节 N：标题」，只在本堂课内跳转，首尾禁用并提示「已是本堂课第一个 / 最后一个环节」 |

**过程性与独立性**

- 每个环节单独请求、单独作答、单独提交，提交成功后只更新当前环节的完成态与步骤条，不打断「下一环节」的连续操作；返回总览时重新向服务端取数，完成状态以后端 `submitted` 为准。
- 切换环节前把当前表单写入 `state.stageAnswers[key]`，切回时还原；各环节的草稿互不覆盖。提交成功后清除该环节草稿。
- `#stage=<key>` 深链可刷新、可前进后退（`popstate` / `hashchange` 同步）；切换教学班、撤回、撤权时会清除深链并释放内嵌预览的 `blob:` 地址。
- 资料阅读**不伪造已完成**：后端没有「已读」回执，因此资料环节只提供阅读与「下一环节」，完成进度仍只按习题提交计算。

## 6. 资产复用与独立分步创建页（第三轮增改）

**用户诉求**：创建预习时想再加题可以直接从原题库导入；资料库或题库里已有的内容可以直接用，不必重新上传 / 重新录入；页面内容堆在一起看着眼花，能分页面的分页面，不能分的优化排列。

**做法：把三个创建表单从弹窗搬成独立页面**

- 「+ 添加环节」仍是一个轻量类型选择弹窗（三张卡片），点进去后**整块 `#group3Content` 换成一张独立创建页**，不再有覆盖在总览之上的长表单。
- 创建页用 `#create=material|quiz|plan` 深链（`pushState` / `popstate` 同步），可刷新、可前进后退；**`?g=&i=` 路由、MENU 编号与 `Group3App.render()` 契约没动**。返回总览或发布成功后清深链并重新向服务端取数。
- 左侧是步骤导航，右侧是当步内容；所有步骤的面板始终在同一张 `<form>` 里，只切换 `hidden`，**切换步骤不丢任何已填内容**（包括已选文件）。最后一步显示发布确认摘要。
- 三个流程的分步：资料阅读 = 选择来源 / 挑选资料 / 发布设置；预习习题 = 基本信息 / 从题库导入题目 / 同步开放资料 / 时间与确认；备课包 = 基本信息 / 课件与随堂题 / 备注与确认。私有备注单独成页。

**做法：资产选择器（不重新导入）**

- 选择器数据直接来自 `GET /overview` 的 `materialVersions[]`（READY 资料版本）与 `questionVersions[]`（题目版本），带搜索框（名称 / 题干 / 题型 / 文件类型）、版本徽标、题型与分值、全选 / 清空与已选计数。
- 选中后提交的是**已有版本 ID**：资料走 `POST /releases`，题目走 `POST /preview-tasks` 的 `questionVersionId`，备课包走 `POST /plans` 的 `materialVersionIds` / `quizQuestionVersionId`。**没有新增接口、没有本地假数据、没有重复上传**。
- 资料环节默认「从课程资源库直接选用」，「上传新文件」只在库里没有时才用；两个来源的最终结果都是同一类真实发布记录。
- 题库里确实没有目标题目时，选择器内提供「+ 题库里没有？新建题目」：新建后重新拉取 `overview`、自动选中新版本并**回到原创建页且保留已填草稿**（草稿只存 UI 表单值，不伪造业务对象）。
- 「课程建设」两个资产页签都加了直达创建页的按钮，可先浏览资产再编排。

**多题导入的真实约束（重要）**

`Group3Requests.PreviewTask` 只有单个 `Long questionVersionId`，`Group3PrepareService.publishPreview()` 也只插入一条 `assignment_item`，**一个预习任务在现有契约下只能绑定一道题**。因此：

- 勾选 N 道题时，页面明确提示并在确认摘要里写明「生成 N 个独立环节（每题一个）」，实际顺序调用 N 次 `POST /preview-tasks`，共享同一开放窗口与导学说明，标题追加「第 k / N 题」。
- 配套资料只在第一个环节发布（后端 `release()` 对同一版本幂等），避免重复发布记录；部分失败时如实提示「已发布 x / N 个环节」并保留页面。
- 若产品要的是「一个环节里包含 N 道题」，需要后端把 `questionVersionId` 扩展为 `List<Long>`、在 `publishPreview()` 里循环插入 `assignment_item`（含 `sortOrder`、题目快照），评审 `docs/api-contracts.md` 后前端只需把 N 次调用改成一次。**这一轮没有放假交互**。
- 未勾选任何题目时为纯资料导学环节，仍是既有真实行为。

**布局整理**

- 教师 / 学生总览：统计卡 + 进度条 + 环节步骤条收进可折叠 `<details>` 概览区；工具栏拆为「视图 / 筛选」与「说明 / 操作」两行；右侧详情面板与独立环节页保持不变。
- 创建页：左侧步骤导航 + 右侧单步内容，最后一步用摘要卡收拢信息；窄屏下步骤导航自动横向铺开、来源卡与摘要改单列。
- 原来「一个弹窗塞 10 个字段」的预习发布表单已不存在，题目、资料、时间分别各占一页。

## 7. 边界与未完成项（需要决策）

1. **没有独立的「环节」实体。** 环节名称取真实资料 / 任务标题，顺序由真实开放时间决定。若需要教师自定义环节名称、拖拽排序、阶段容器（如「课前 3 天 / 课前 1 天」）、或保存未发布的编排草稿，必须由第 3 组后端新增环节实体与 CRUD / 排序 / 对象权限接口，并在 `docs/api-contracts.md` 评审后再接前端。当前版本没有用 localStorage 伪造这些数据。
2. **章节筛选的数据缺口。** 教师资源列表 `selectTeacherResources` / `selectReadyResourceVersions` 不返回 `unitId` 与知识点 ID，因此时间轴卡片无法反查「这份资料归到哪一章」。归档动作是真实落库的（上传 `unitId`、题目 `knowledgePointIds`），但按章节筛选时间轴需要后端补返回字段。
3. **备课包没有开放时间字段。** 目前按关联课次的 `scheduledAt` 定位，没有课次时间时用创建时间；它是教师私有节点，不影响学生可见范围。
4. **发布预习时勾选的同步资料**沿用后端既有行为：会对同一资源调用 `release`，替换该班未结束的旧发布。若产品希望一次任务内多份资料独立设置窗口，需要另立契约。
5. **课程详情页属于第 2 组范围**，本轮未伪造。当前通过页面顶部的课程 / 教学班上下文 + 时间轴上传入口完成「从课程进入资料上传」的链路。
6. 学生端日期分组按客户端本地日历显示（仅展示用途），时间轴不显示倒计时作为权威截止依据。
7. **环节能删除，但仍不能改时间 / 改内容。** 第五轮补了真实的「删除环节」（归档软删除，见第 9 节）；但 `preview-tasks` 与 `plans` 仍只有发布与读取接口，习题环节和备课包不能改开放时间、不能编辑内容。若产品要求环节可编辑，需要后端补状态机、对象权限、幂等与目标快照处理，并在 `docs/api-contracts.md` 评审后接入。页面不提供假按钮。
8. **「一堂课」用日期近似，不是数据库课次。** 第五轮已改为按「课程 / 教学班 / 上课日期」分组、每堂课从 1 重新编号（见第 5、9 节）；但学生资料与任务接口仍不返回 `lessonId`，教师资料发布也不带，所以分组依据是 `opensAt` 的本地日期。同一天同班有两节课时会被合成一组；要严格按课次分组，或支持教师自定义顺序 / 环节名称 / 拖拽排序，需要后端补 `lessonId` 或环节实体与排序字段。
9. **序号是展示层派生值**，不是数据库持久编号。教师撤回、发布、学生权限变化后，序号会随可见集合重算；不要在外部系统里把「第 N 环节」当成稳定 ID，稳定标识仍是 `key`（来自 `versionId / assignmentId / planId`）。
10. **一个预习任务只能绑定一道题（本轮新发现）。** 见第 6 节；多题导入当前按「每题一个独立环节」真实发布，未伪造单任务多题。要改成单环节多题必须扩展后端 `PreviewTask` 与 `publishPreview()`。
11. **创建页草稿是 UI 状态。** `#create=` 深链与 `sessionStorage` 只保存表单值以便新建题目后回来不丢失，不保存任何业务对象；刷新页面或发布成功后草稿清除，时间轴数据始终来自服务端。
12. **「提交本环节预习」按钮由开放窗口控制，不是后端渲染或缺失功能。** 后端 `studentPreviewDetail()` 按服务器时间返回 `state = OPEN / UPCOMING / CLOSED`，`submitPreview()` 也会对窗口外提交返回 409「预习任务尚未开放 / 已截止」并拒绝重复提交。前端 `loadStageQuiz()` 只在 `state === OPEN && !submitted && 有题目` 时让按钮可用；其余状态按钮**保留但禁用**，并在作答区显示具体原因（截止 / 开放 / 提交时间）、把输入控件置为只读、把页脚提示改为「不会写入服务端」，避免按钮静默消失却仍可白填。要验证提交流程，需发布一个开放窗口覆盖当前时间的习题环节；种子数据里的旧任务（如 10/26–10/30）在当前日期已全部截止。

## 9. 删除环节与按堂课编排（第五轮增改）

**删除环节**

- 入口：教师端环节卡片、右侧详情面板、独立环节编辑页；学生端没有删除入口，也不会收到删除按钮。
- 流程：二次确认弹窗写明后果（学生立即不可见、本页不提供恢复、资料本体及版本一并归档、学生已提交的作答与成绩保留、本堂课剩余环节重新编号）→ `POST /education/group3/stages/remove` → 成功后清 `#stage` 深链、清 overview 缓存、重新拉取真实数据并重算编号。
- 后端是**归档软删除**：`edu_resource.status` / `edu_assignment.status` / `edu_lesson_plan.status` 置 `ARCHIVED`，资料同时结束仍有效的发布记录；`selectPlans`、`selectTeacherPreviewTasks`、`selectStudentPreviewTasks`、`selectStudentPreviewTask` 补上 `status <> 'ARCHIVED'` 过滤（资源侧三个查询原本已过滤）。不物理删除任何行、不改表结构、无需数据迁移。契约与幂等口径见 [接口协作约定](api-contracts.md) 末节。
- 删除粒度是**整个业务对象**：删资料环节会连同该资料的所有版本和发布一起归档，不只是从这一堂课里摘掉。若产品要求「同一份资料在 A 堂课保留、B 堂课移除」，需要后端补独立的环节实体或按课堂的发布关系表，前端无法在现有数据模型下伪造。
- 仍保留原有的「撤回发布」：它只结束发布、资料本体与版本仍留在资源库，适合「暂时下架、稍后再发」；「删除环节」是更彻底的操作，两者不能混用。

**按堂课编排**

- 一堂课 = 课程 + 教学班 + 上课日期（`opensAt` 本地日）；`numberStages()` 按组独立编号，`buildStageGroups()` 生成分区，`stageNodesOf()` 提供组内上下导航。
- 总览折叠区标题改为「按堂课总览 · 共 X 堂课 / Y 个环节」，步骤条按堂课分区；日期分组标题显示「本堂课 N 个环节 · 1–N 号」；顶部新增「按课堂切换」chips，切换即换教学班 / 课程并重新取数。
- 独立环节页面包屑显示「日期 · 课程 · 教学班 · 第 N / M 环节」，上下按钮只在本堂课内跳；创建页写明目标课堂与开放日期决定归属。
- 删除、新增、撤回、切换课堂都会重新计算本堂课编号，序号仍是展示层派生值，不是持久 ID。
