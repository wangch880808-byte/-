## 页面注册与生命周期

各组在 `frontend/pages/` 下维护自己的业务文件，并在对应角色 HTML 中按依赖顺序加载。脚本放在 `shell.js` 之前时，加入 `window.EDU_PAGES` 队列；延后加载可调用 `EduShell.registerPage(g, i, page)`。同一位置只能注册一个模块，重复覆盖会报错。

页面声明 `roles`、`permission`、`route`。需要教学班时声明 `requiresContext: 'class'`；只需要课程时用 `'course'`。仅真正不读取私有数据的页面可使用 `allowAuthenticated: true`。权限与路由须和 1A/对应业务组确认，不能只改前端来绕过服务端校验。

`mount(host, context, lifecycle)` 的第三个参数向后兼容既有页面：

- `lifecycle.signal`：切页、切换上下文、拒绝访问、退出或页面恢复前会取消。传给 `EduApi.get/request` 和订阅。
- `lifecycle.isCurrent()`：异步返回后、更新 DOM 前检查。响应即使忽略取消，也不能再写回旧页面。
- 页面仍需通过 `unmount()` 关闭定时器、实时连接和第三方组件。不得把教师私有详情放到外壳之外而不清理。

使用方式（`BusinessApi`、`renderBusinessPage` 由对应业务组提供，不是本轮新增的实际接口）：

```js
const page = {
  roles: ['teacher'],
  permission: '<与服务端确认的权限标识>',
  route: '<getRouters 中的实际路由或组件>',
  requiresContext: 'class',
  async mount(host, context, lifecycle) {
    const result = await BusinessApi.load(context, { signal: lifecycle.signal });
    if (!lifecycle.isCurrent()) return;
    renderBusinessPage(host, result);
  },
  unmount() { /* 取消本页自己的订阅、定时器与组件 */ }
};
```

未校验身份和上下文前不挂载业务页。已授权页面延后注册后，外壳可以恢复其深链接或默认入口；未授权页面不会因此被打开。多角色账号也只显示当前角色视图允许的页面。

## 第 6 组顶部通知接入

6B 在已经注册的通知页面上增加元数据，1B 外壳负责顶部入口和跳转，不猜测通知接口路径：

```js
page.headerEntry = {
  label: '通知',
  async getUnreadCount(context, { signal }) {
    // NotificationApi 由第 6 组实现，内部复用 EduApi，并正确处理 403。
    return NotificationApi.getUnreadCount(context, { signal });
  }
};
```

`getUnreadCount` 可省略，此时只显示入口，不伪造数量。提供时必须返回非负安全整数；0 隐藏角标，超过 99 显示 `99+`，失败显示不可用状态，不将失败当作 0。403 隐藏该入口。页面未注册、角色不符、权限或路由不足时，不显示入口、不请求数量。声明 `requiresContext` 的页面只在所需上下文完整时显示入口。

未读请求随上下文切换、重新核验身份和退出取消；迟到响应不能写入新账号或班级。通知已读操作成功后，6B 调用 `EduShell.refreshHeader()` 刷新数量。外壳不主动轮询，也没有新增模拟通知页或假接口。

## 交给 2A 的上下文补充要求

默认 `options/check` 路径仍是待确认草案，不宣称已获 2A 确认。前端本轮进一步采用以下拒绝默认值：

1. `options` 的课程 ID 不重复，同一课程下的同角色教学班不重复，ID 为正整数字符串或安全整数。
2. `options` 给出 `bindingId` 时，`check` 必须回传相同 ID；旧收藏或会话中的绑定发生变化时，不静默切换至新绑定。
3. `check` 返回最新 `canPublish/canGrade` 布尔值；缺失或为 false 时一律关闭相关按钮，不回退到旧 options 中的授权。
4. 若 `check` 才返回 bindingId，前端保存其权威值到只读上下文、会话和 URL；后续刷新重新校验。
5. 每个业务请求仍需服务端实时检查成员和操作权限，前端能力标记不能替代撤权检查。

需要 2A 提供正常、空、无权限、失败的真实接口和跨班、退班、撤权案例；需要 1A 提供受限教务管理员。1B 的模拟测试不替代这些联调结果。
