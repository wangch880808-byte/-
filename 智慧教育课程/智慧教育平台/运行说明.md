# 第一、二、三组对接版运行说明

交付日期：2026-11-10。只有一套正式前端：`frontend/` 若依 Vue3 工程，保留第一组原来的登录、布局、菜单与业务页面；第二组教务／课程业务、第三组课程资源与备课预习业务接入其中。后端仍从 `backend/ruoyi-admin/src/main/java/com/ruoyi/RuoYiApplication.java` 启动。

本轮完成前端生产构建、后端八个模块打包及静态核对。按要求没有启动项目、连接或修改你的数据库，也没有执行接口／浏览器联调；以下步骤由你执行。交付包是源码包，不包含依赖和编译产物。

## 1. 解压并检查环境

将 ZIP 解压到 `D:\`，得到 `D:\smart-edu-g12`。以下命令均以这个路径为例；你可以改成自己的实际解压路径。不要覆盖现有工程，先在独立目录试用。

需要 JDK 17、Maven 3.9、Node.js 20.19 或更新的兼容版本、pnpm 11.25.0、MySQL 8.0.16+、Redis。MySQL 必须支持 CHECK、生成列和 utf8mb4_0900_ai_ci。MySQL、Redis 的服务要由你自行启动。

在 VS Code 打开 `D:\smart-edu-g12`，选择“终端 → 新建终端”，使用 PowerShell，检查：

```powershell
cd 'D:\smart-edu-g12'
java -version
mvn -version
node -v
pnpm -v
```

`java` 和 Maven 显示的 Java 都应为 17。如果未安装 pnpm，可在 Node 安装完成后执行 `npm install -g pnpm@11.25.0`。首次安装和构建需要网络下载依赖。

## 2. 准备数据库（二选一）

### A. 新建独立演示库（首次运行建议使用）

在 Navicat、DBeaver 或 MySQL 客户端执行：

```sql
CREATE DATABASE smart_edu_g12 CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
```

然后选中这个**新建的空库**，导入项目中的 `sql/install-fresh.sql`。这一份已经按顺序合并若依系统表、定时任务表、教学表、虚构演示数据、登录账号、身份只读视图、课程菜单与权限，不需要再逐个导入其他 SQL。

如果使用命令行，在 PowerShell 先执行：

```powershell
mysql -h 127.0.0.1 -P 3306 -u root -p --default-character-set=utf8mb4
```

输入数据库密码后，在 **mysql 提示符** 中执行：

```sql
USE smart_edu_g12;
SOURCE D:/smart-edu-g12/sql/install-fresh.sql;
SHOW TABLES;
```

路径有中文或空格时建议用图形客户端导入。导入失败要先看第一条 SQL 错误，不要继续重复执行演示数据脚本。

**注意：`install-fresh.sql` 中包含若依上游的重建表语句，只用于新空库，不能导入你已有的业务库。**

全新安装后生成的演示账号：

| 账号 | 登录入口 | 密码 |
|---|---|---|
| admin | 管理员 | Edu@123456 |
| teacher | 教师 | Edu@123456 |
| student | 学生 | Edu@123456 |
| student2、student3、student4 | 学生 | Edu@123456 |

这些是本包初始化的虚构演示账号。验证码需要填写页面显示的内容。管理员和演示师生归属同一个“演示学校”，便于测试建学期、建班和课程绑定。

### B. 沿用已有的第一组／第二组数据库

先备份原库，再选中原库，执行 `sql/upgrade-group12.sql`。前提是该库已经有本工程原有的 `sys_*` 和 `edu_*` 基础表；它不是从任意数据库升级的通用脚本。

升级脚本只补当前学期字段／唯一约束、公共身份目录视图以及第二组菜单和权限；**不导入演示账号、不修改现有密码、不清空业务数据**。需要建视图和临时存储过程权限。若库里已经设置多个当前学期，应先人工确认保留哪一个，不能让脚本自行决定。

第三组资源、题库、备课和预习复用 M0 已有的 `edu_resource*`、`edu_question*`、`edu_lesson_plan`、`edu_assignment*` 等表，本版**没有新增表结构**；新库总脚本和上一轮已有库升级脚本已包含这些表，不需要为第三组单独再执行建表脚本。

已有数据库继续使用原来的账号密码，不要套用上面的演示密码。没有任课关系、在班记录或已发布课程时，教师／学生看到空列表是正常情况。

## 3. 填写后端本地配置

回到 PowerShell，在项目根目录执行：

```powershell
Copy-Item -LiteralPath '.\backend\.env.example' -Destination '.\backend\.env'
```

打开 `backend/.env`，填写：

```dotenv
RUOYI_DB_URL=jdbc:mysql://127.0.0.1:3306/smart_edu_g12?useUnicode=true&characterEncoding=utf8&zeroDateTimeBehavior=convertToNull&useSSL=false&serverTimezone=Asia/Shanghai&forceConnectionTimeZoneToSession=true
RUOYI_DB_USERNAME=root
RUOYI_DB_PASSWORD=你的数据库密码
RUOYI_TOKEN_SECRET=你生成的随机密钥
RUOYI_REDIS_HOST=127.0.0.1
RUOYI_REDIS_PORT=6379
RUOYI_REDIS_DATABASE=14
RUOYI_REDIS_PASSWORD=
RUOYI_UPLOAD_PATH=./data/uploads
```

沿用已有库时，把 URL 里的 `smart_edu_g12` 改成实际库名。Redis 有密码时填写对应值。Redis DB 14 要留给本项目，避免和其他正在使用的项目共用。

在 PowerShell 生成随机令牌密钥：

```powershell
[guid]::NewGuid().ToString('N') + [guid]::NewGuid().ToString('N')
```

将输出的整行粘贴到 `RUOYI_TOKEN_SECRET=` 后面。配置项每行一个，不加引号，不把真实 `.env` 提交 GitHub。已有 `.env` 时只编辑它，不重复复制覆盖。

## 4. 安装依赖并构建

在项目根目录执行：

```powershell
.\scripts\build-group12.ps1
```

脚本只安装依赖和构建，不启动服务、不导入数据库。等到最后显示“构建完成”再继续。

也可以分步执行：

```powershell
cd 'D:\smart-edu-g12\frontend'
pnpm install --frozen-lockfile
pnpm run build
cd ..
mvn -B -f backend/pom.xml -pl ruoyi-admin -am -DskipTests clean package
```

前端生成 `frontend/dist/`；后端生成 `backend/ruoyi-admin/target/ruoyi-admin.jar`，并将前端产物打入 JAR。`-DskipTests` 跳过测试执行，本轮交付也没有声称运行测试通过。

PowerShell 如果提示禁止运行脚本，只在当前终端执行 `Set-ExecutionPolicy -Scope Process Bypass`，然后重新执行脚本即可，不需要修改系统全局策略。

## 5. 启动后端

确认 MySQL、Redis 已启动。在第一个终端执行：

```powershell
cd 'D:\smart-edu-g12'
.\backend\run-local.ps1
```

等待若依启动成功，保留这个终端。默认后端端口为 **8080**。如果原项目仍占用 8080，先在原项目的终端按 `Ctrl+C` 停止它，再启动本包。

不要直接双击启动类后期望 IDEA 自动读取 `.env`；这份 `.env` 由 `run-local.ps1` 载入。使用 IDEA 时应自行把同名配置填入运行配置的环境变量，并选择 JDK 17。

## 6. 打开前端（两种方式选一种）

**只看效果：** 完成前端构建和后端打包、启动后端后，浏览器打开：

`http://127.0.0.1:8080/vue/#/login`

这是同一个 Vue3 工程的打包页面，不是旧静态兼容版，不需要启动第二个前端服务。

**需要修改前端代码：** 新建第二个终端：

```powershell
cd 'D:\smart-edu-g12\frontend'
pnpm dev
```

浏览器打开 `http://127.0.0.1:5173/#/login`。5173 通过 `/dev-api` 代理到 8080，两个终端都需要保留。旧项目若占用 5173，先停掉旧前端；本项目不自动换端口。

## 7. 建议自行验证的顺序

1. 管理员登录，展开“教务组织”，检查组织架构、学期、班级、教师、学生页面；原来的菜单默认收起和组织节点展开／收起仍保留。
2. 检查“系统管理”的用户、角色、菜单和审计日志；用户／角色导入导出、创建用户时管理员角色分配仍走第一组功能。
3. 班级设置为“开放”，给 teacher 授权，给 student 入班；确认任课类型、发布／评分权限位和有效期。
4. 教师登录 → 我的课程 → 新建课程 → 编辑简介、章节与知识点 → 绑定自己被授权的教学班 → 发布课程。课程和班级须属于同一组织。
5. 学生登录 → 我的课程，查看已发布且本人有效在班的课程与目录；顶部切换课程、教学班。
6. 教师登录 → 我的课程 → 打开某门课程 → 课程建设：上传 PPTX／PDF／图片／文档，确认处理成功并生成页码；替换版本后按班发布或撤回。再进入课前准备：维护题库题目、备课方案与材料顺序，发布预习任务并设置开放／截止／解析公布时间。
7. 学生登录 → 我的课程 → 打开某门课程 → 课程资料：只能看到本人班级当前开放版本，预览与下载地址受控；课前学习：在开放后作答，解析公布前看不到答案，重复提交保持幂等。教师撤回或学生退班后，旧页面／旧下载地址应返回无权限。
8. 管理员撤销教师授权或让学生退班，再让对应账号刷新旧地址；服务端应拒绝失效访问。协同教师只读课程，不能改负责人课程或查看外班名单。
9. 检查没有课程、未发布、班级停用等空状态，以及教师／学生直达管理页面时的权限拦截。

课程章节与知识点属于第二组；资料版本、题库、备课与预习属于第三组。课堂、统一作业评分、讨论、统计和 AI 的完整功能仍不在本轮三组对接交付范围。对应未实现菜单保留空白，课程页相关标签显示尚未开放，没有模拟业务数据。第三组课件转换在请求线程内同步执行，PPTX 按静态页渲染，复杂动画、音视频和切换效果不还原；文件保存在 `RUOYI_UPLOAD_PATH/education` 下。

## 8. 常见问题

- **后端启动了但 5173 打不开：** 没有启动 Vite；直接访问 8080/vue/，或者按第 6 步另开终端运行前端。
- **8080/vue/ 空白或 404：** 先构建前端，再重新打包后端并重启；不能只复制源码后直接运行旧 JAR。
- **数据库 Access denied：** 核对本包 `backend/.env`，不是另一份工程的配置；确认账号允许连接实际主机和数据库。
- **登录后课程为空：** 检查课程 ACTIVE、班级 ACTIVE、未解绑、学生在班／教师授权有效，且登录入口角色正确；账号有 teacher 角色本身并不等于被授权任课。
- **新增页面没有权限或菜单：** 检查是否导入本包菜单权限脚本，并退出后重新登录。已有库不会自动替你创建师生角色或业务关系。
- **控制台出现 /shell/*.js 的 MIME 错误：** 这是旧静态地址或旧缓存；改用本包上述 Vue 地址并强制刷新，不再以 student.html 作为业务入口。

停止项目时，在运行中的终端按 `Ctrl+C`。不要删除数据库或上传目录来停止服务。
