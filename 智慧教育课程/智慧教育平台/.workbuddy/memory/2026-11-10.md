## 第八轮：刷新仍是旧页面的真正根因（304）
- 用户二次反馈截图仍是旧「配置与状态 / 可执行操作」两栏。核对服务端只有一份 group3.js，旧文案 0 处、新文案齐全；系统代理 `ProxyEnable=0`，排除服务端残留与代理。
- **根因**：用 `If-Modified-Since: Fri, 01 Feb 1980 00:00:00 GMT` 请求静态资源，服务端返回 **304**（响应头虽带 no-store）。jar 可复现构建使时间戳恒为 1980，浏览器刷新时发起条件请求 → 304 → 继续用缓存里的旧 JS，所以 `no-store` 与 Ctrl+F5 都救不了已存在的旧缓存条目。
- 修复：`application.yml` 的 `spring.web.resources.cache` 增加 `use-last-modified: false`，禁用 Last-Modified / 条件请求，静态资源每次返回 200 完整内容；`frontend/README.md` 同步说明。
- 首次仍需重新加载 HTML（旧标签页里缓存的是不带 `?v=` 的 teacher.html），因此给出全新 URL `/teacher.html?g=1&i=2&v=2#stage=...` 绕开所有缓存 key；登录态按 origin 保存，不受 query 影响。
- 经验：Spring Boot 打包静态资源时，`no-store` 必须配合 `use-last-modified: false` 才能真正击穿旧缓存；只加前者会留下 304 陷阱。
